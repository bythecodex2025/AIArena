# AI 대전에 적합한 게임의 속성

## 1. 문서 목적

사용자가 LLM으로 게임 AI를 작성하고 내장 AI와 대전하는 코딩 게임을 설계할 때 필요한 게임 구조, AI 인터페이스, 평가 방식과 안전 조건을 정의한다.

좋은 AI 대전 게임은 규칙이 복잡하기만 한 게임이 아니다. 입력 상태가 명확하고, 합법 행동을 쉽게 선택할 수 있으며, 짧은 경기 안에서도 전략 차이가 점수로 드러나야 한다.

## 2. 핵심 설계 속성

### 2.1 완전하고 구조화된 상태

AI가 판단에 필요한 정보는 하나의 직렬화 가능한 상태 객체로 제공한다.

- 보드, 유닛, 자원, 차례, 남은 턴
- 현재 가능한 모든 합법 행동
- 점수와 승리 조건 진행도
- 공개된 최근 행동 기록

AI가 UI, DOM, 전역 변수 또는 숨은 엔진 상태를 읽어야 해서는 안 된다.

### 2.2 유한한 행동 공간

한 차례에 선택 가능한 행동 수가 너무 많으면 LLM이 만든 코드가 쉽게 실패한다. 권장 행동 수는 평균 5~40개다.

엔진이 `legalActions`를 생성하고 AI는 그중 하나를 반환하게 한다. 이 방식은 좌표 오류, 규칙 위반, 포맷 오류를 줄이고 사용자가 전략에 집중하게 한다.

### 2.3 짧지만 전략적인 경기

브라우저 프로토타입 기준 한 경기는 20~60턴, 자동 대전은 수 초 이내가 적당하다.

- 즉시 보상: 적 공격, 자원 획득
- 중기 목표: 거점 점령, 진형 형성
- 장기 목표: 핵심 유닛 격파 또는 누적 점수

세 시간축이 함께 있어야 단순 랜덤 AI와 전략 AI의 차이가 드러난다.

### 2.4 복수의 승리 경로

단일 목표만 있으면 하나의 정답 전략으로 수렴하기 쉽다.

- 상대 핵심 파괴
- 거점 점수 누적
- 제한 턴 종료 시 우세

최소 두 가지 승리 경로를 두면 공격형, 방어형, 점령형 AI가 경쟁할 수 있다.

### 2.5 제한된 불확실성

AI 평가의 재현성을 위해 순수 운 요소는 낮게 유지한다.

- 공격 피해는 고정값 권장
- 무작위 맵은 시드를 저장
- 선공·후공을 교대
- 여러 경기 평균으로 평가

랜덤 요소가 필요하면 AI가 확률을 상태에서 확인할 수 있어야 한다.

### 2.6 점진적 상태 변화

각 행동이 다음 의사결정에 의미 있는 영향을 줘야 한다.

- 위치 이동
- 체력 감소
- 자원 충전·소모
- 거점 소유권 변화
- 재사용 대기시간

상태 변화가 너무 작으면 전략 차이가 드러나지 않고, 한 번의 행동이 지나치게 강하면 운과 선공 효과가 커진다.

### 2.7 관전 가능한 설명성

사용자는 AI가 왜 이겼는지 화면에서 이해할 수 있어야 한다.

- 선택한 유닛과 목적지 강조
- 공격·점령·회복 애니메이션
- 행동 로그
- 체력과 자원 변화
- 종료 사유와 핵심 통계

### 2.8 안전한 실행

사용자 코드는 별도 Worker 또는 서버 샌드박스에서 실행한다.

- 한 행동당 제한 시간
- 입력 상태 복사본 전달
- 반환값을 합법 행동 목록과 재검증
- 무한 루프 시 Worker 종료
- 출력과 오류 길이 제한

브라우저 Worker는 프로토타입 용도이며 공개 서비스는 격리 컨테이너가 필요하다.

## 3. 권장 AI 함수 인터페이스

```javascript
function chooseAction(state, me) {
  return state.legalActions[0];
}
```

### 상태 설계 원칙

- JSON으로 직렬화 가능
- 읽기 전용으로 취급
- 플레이어 방향에 따라 구조가 달라지지 않음
- 모든 객체에 안정적인 ID 제공
- 좌표와 인덱스 변환 규칙 명시
- 합법 행동 객체는 그대로 반환 가능

### 행동 객체 원칙

```javascript
{ id: "move:u1:18", type: "move", unitId: "u1", to: 18 }
{ id: "attack:u1:u4", type: "attack", unitId: "u1", targetId: "u4" }
{ id: "capture:u2:24", type: "capture", unitId: "u2", target: 24 }
{ id: "guard:u3", type: "guard", unitId: "u3" }
```

AI는 객체를 새로 조립하기보다 `id` 또는 합법 행동 객체를 그대로 반환할 수 있게 한다.

## 4. 전략 깊이를 만드는 요소

### 유닛 역할 비대칭

- 빠르지만 약한 정찰형
- 느리지만 체력이 높은 방어형
- 사거리가 긴 공격형
- 보호해야 하는 핵심 유닛

### 자원과 기회비용

이동, 공격, 특수 행동이 같은 에너지를 소비하면 AI가 단기 공격과 장기 준비를 비교하게 된다.

### 공간 목표

중앙이나 거점에 점수를 부여하면 단순 추격 대신 위치 전략이 생긴다.

### 행동 순서

매 턴 하나의 행동만 허용하면 판단이 명확하다. 여러 행동을 허용한다면 행동 포인트를 사용하고 남은 포인트를 상태에 명시해야 한다.

## 5. 공정한 평가 방식

### 기본 매치 구성

- 동일 맵에서 선공·후공 교대
- 최소 10경기
- 가능하면 여러 고정 시드 사용
- 엔진 버전과 AI 코드 스냅샷 저장

### 권장 점수

```text
경기 점수 = 승리 3점 + 무승부 1점 + 패배 0점
보조 지표 = 남은 핵심 체력 + 거점 점수 + 상대 피해량
```

보조 지표는 동점 처리에만 사용해 승리 목표가 왜곡되지 않게 한다.

### 오류 처리

- 시간 초과: 해당 경기 패배
- 예외 발생: 해당 경기 패배
- 합법 목록에 없는 행동: 해당 경기 패배
- 반복 상태: 무승부
- 최대 턴 도달: 점수와 핵심 체력로 판정하거나 무승부

## 6. 피해야 할 특성

- 행동 공간이 수백~수천 개인 게임
- 설명하기 어려운 숨은 규칙
- UI 좌표를 직접 반환해야 하는 API
- 한 번의 무작위 결과로 승부가 결정되는 구조
- 경기가 지나치게 길거나 끝나지 않는 구조
- 합법 수 생성까지 사용자에게 요구하는 인터페이스
- 플레이어마다 상태 객체 형식이 다른 구조
- 게임 엔진과 화면 로직이 결합된 구현

## 7. 예제 게임 선정 체크리스트

- [ ] 상태를 JSON 하나로 표현할 수 있는가?
- [ ] 엔진이 합법 행동을 전부 제공하는가?
- [ ] 평균 행동 수가 5~40개인가?
- [ ] 60턴 이내에 대부분 종료되는가?
- [ ] 랜덤 AI보다 나은 휴리스틱을 쉽게 작성할 수 있는가?
- [ ] 고급 사용자는 탐색·평가 함수를 적용할 수 있는가?
- [ ] 선공·후공 교대로 공정성을 확보할 수 있는가?
- [ ] 인간이 관전하며 상태 변화를 이해할 수 있는가?
- [ ] 직접 플레이 테스트가 가능한가?
- [ ] 오류와 승패 원인을 명확히 표시할 수 있는가?

## 8. 이번 예제에 적용할 결론

이번 복합 예제는 7×7 격자 전술 게임으로 설계한다.

- 각 플레이어는 핵심 1기와 역할이 다른 전투 유닛 3기를 보유
- 이동, 공격, 방어, 거점 점령 행동
- 상대 핵심 파괴 또는 거점 점수 7점 획득으로 승리
- 공격 피해는 고정해 재현성 확보
- 한 턴 한 행동, 최대 60턴
- AI는 엔진이 제공하는 `legalActions` 중 하나를 반환
- 사용자 직접 플레이와 랜덤 AI 자동 대전 지원

이 구조는 틱택토와 동물장기보다 상태와 전략이 복잡하지만, 제출 함수의 형태는 동일하게 단순하게 유지한다.
